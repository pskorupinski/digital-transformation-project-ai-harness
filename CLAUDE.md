# CLAUDE.md

Harness for **digital transformation projects**: turning a business's existing process into a
web solution, from discovery to a working vertical slice. Humans own discovery and every
decision; Claude structures, proposes and builds — always traceably.

## Process and file roles

| Step | Owner | Command | Reads | Writes |
|---|---|---|---|---|
| 01 Brief | human | — | — | `docs/01-brief.md` |
| 02 Integrations | human | — | brief §7 | `docs/02-integrations.md` |
| 03 Features | Claude → human | `/03-features` | 01, 02 | `docs/03-features.md`, brief §10 |
| 04 Architecture | Claude → human | `/04-architecture` | 01–03, decisions | `docs/04-architecture.md`, proposed decisions |
| 05 Spec | Claude → human | `/05-spec F-nn` | 03, 04 | `docs/05-specs/F-nn-<slug>.feature` |
| 06 Build slice | Claude → human | `/06-build-slice F-nn` | 02–05, decisions | `backend/`, `frontend/`, status updates |

Three kinds of truth — keep them apart:
- **how** we work → this file · **what** we build → `docs/` · **why** we chose it → `decisions.md`

## Traceability IDs

`§n` brief section · `A-nn` assumption (brief §10) · `I-nn` integration · `F-nn` feature ·
`S-nn` scenario (`F-nn/S-nn`) · `D-nn` decision. Every generated artifact cites its sources with
these IDs. Missing information becomes a new `A-nn` row in brief §10 — never a silent guess.

## Guardrails

1. **Stay in scope.** Build only features whose scope has no `?`. Never invent business facts.
2. **Architecture is a contract.** Follow `docs/04-architecture.md` and accepted decisions.
   If reality disagrees, stop and propose a change (a `proposed` row in `decisions.md`).
3. **No new dependencies without asking.** Pre-approved: `react-router` (when a slice needs a
   second page).
4. **Tests come from scenarios.** One test per Gherkin scenario, named `test_s01_<slug>`
   (backend) or `it('S-01 …')` (frontend), with the scenario ID in the docstring/title.
5. **Small steps, visible checkpoints.** Present the plan before coding. Commit at each green
   checkpoint (`F-nn: <step>`). Never push.
6. **Generated migrations are reviewed.** Show every autogenerated Alembic script and flag
   drops, renames and type changes before applying it.
7. **No visual polish.** Brand lives only in `frontend/src/theme.css` tokens; components use
   tokens, never raw colours. Layout = plain semantic HTML.
8. **Hooks are the quality gate.** Lint/format runs after every edit; tests run before a turn
   ends. Don't bypass or silence them — fix the cause or explain why the failure is expected.

## Stack (D-02)

- `backend/` — FastAPI · SQLAlchemy 2.0 typed models · Pydantic schemas · Alembic · pytest · ruff
  - `app/models/` ORM (import every model in `app/models/__init__.py`)
  - `app/schemas/` API contracts (separate from ORM on purpose)
  - `app/services/` business logic, owns transactions; routers in `app/api/` stay thin
  - `app/integrations/` ports + fake adapters (D-01); mock-provider routes in `mock_providers.py`
- `frontend/` — React + Vite + TypeScript · vitest + Testing Library · oxlint
  - all calls through `src/api/client.ts` to the relative `/api` path
- `docker-compose.yml` — Postgres 16 (`app`, `app_test`), backend :8000, frontend :5173

## Integrations pattern (D-01)

For each `fake` row in `docs/02-integrations.md`: a `Protocol` port the services depend on, a
`Fake…Adapter` mirroring the real contract, and a factory choosing by `INTEGRATIONS_MODE`.
If the real system calls back asynchronously, the fake simulates it: a mock-provider route
schedules a `BackgroundTask` that sends the event over HTTP to **our real inbound route**.

## Commands

```bash
docker compose up --build -d                                   # start everything
docker compose exec backend pytest                             # backend tests
docker compose exec backend alembic revision --autogenerate -m "<msg>"
docker compose exec backend alembic upgrade head
docker compose exec frontend npm test                          # frontend tests
docker compose exec frontend npm run typecheck
docker compose logs -f backend                                 # debug
```

Frontend http://localhost:5173 · API docs http://localhost:8000/docs
